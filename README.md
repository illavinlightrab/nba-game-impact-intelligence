# NBA Game Impact Agent

基于 NBA 数据、比赛概率、市场比较、新闻证据与模型分析实现的本地研究工作台。前端已移除回测与模拟交易模块，原有后端接口和记录保留。

**当前版本：真实数据源、自动新闻/伤病采集、出场影响量化、Elo 基线预测，以及支持网页搜索和连续追问的球队/球员分析窗口。** 已实现伤病残差模型的训练、验证和条件启用流程；目前没有通过真实历史样本验证的伤病模型，默认胜率仍由 Elo 生成。市场报价和 NBA 赛程仍需手动同步。

### 常见启动问题

- **`Address already in use` / 端口已占用**：检查是否已有后端或前端在运行，避免重复启动。确认已有程序属于本项目后，再决定使用或停止它。
- **页面提示后端没有返回有效数据**：检查后端终端是否仍在运行，以及 `8000` 端口是否正确。
- **页面提示数据库不可用或迁移尚未执行**：先检查数据库健康接口，再检查 `DATABASE_URL` 和迁移版本。
- **`待预测`**：赛程已经加载，但该场尚未保存预测。刷新只读取已有数据，需选择支持的比赛并点击“运行 Agent”。
- **回答后找不到输入框**：当前版本会在窗口底部保留“继续追问”输入区，长回答在对话区内滚动。旧页面需刷新加载新版；刷新会清空当前会话。
- **网页搜索不可用**：检查后端提示和模型配置；可关闭“网页搜索”使用本地证据，或配置支持搜索工具的模型与账户。

## 使用顺序

1. 在“数据与设置”同步球队。
2. 在“模型分析”选择 `2025-26`，再到“数据与设置”同步历史常规赛赛果；可补充 `2024-25` 等更早赛季作为预热。仅有未来赛程不能建立球队历史实力。
3. 在“模型分析”切换到后端配置的当前赛季（默认 `2026-27`），再到“数据与设置”同步赛程。在“比赛预测”选择尚未开赛的常规赛或季后赛，点击“运行 Agent”。季前赛、全明星、附加赛及未知类型暂不支持预测。
4. 手动保存研究报价，或按下节步骤读取对应 Polymarket 订单簿。
5. 更新赛果、新闻或报价后，重新运行 Agent。已保存预测属于当时的快照，不会因刷新而重新计算。
6. 在“模型分析”选择球队/球员，询问人员配置、球队评价，或生成分析报告。回测与模拟交易不再出现在前端。

## 模型分析窗口

### 提问与连续追问

1. 打开“模型分析”，在输入框提问，例如：**“分析亚历山大 2025-26 赛季季后赛的表现。”**
2. 检查回答中的“已识别”对象、赛季和比赛类型。问题里明确指定的范围优先于下拉框；下拉框用于提供问题未说明的默认范围。
3. 回答完成后，在底部 **“继续追问”** 输入框接着提问，例如：“展开解释刚才的第二点”或“那他常规赛呢？”点击发送或按 `⌘/Ctrl + Enter`，无需新建对话或重复选择球员。

- **输入区**吸附在窗口底部，长回答在对话区内滚动；回答结束后自动聚焦输入框。
- **快捷分析**：“生成球队报告/生成球员报告”和“人员配置分析”使用当前范围，生成后也可继续追问。“停止生成”中断当前回答。
- **问题识别**：英文全名、SGA/亚历山大等常见称呼先匹配本地目录；其他称呼通过结构化模型识别并核验。对象不唯一时请求澄清；复杂问题可能额外产生一次模型调用。
- **范围限制**：当前只组装一个对象、赛季和比赛类型的详细统计，多对象或多范围问题可能需要澄清。结构化问题识别仅使用当前问题与默认范围，不读取完整历史；回答模型会接收近期对话，因此复杂的历史指代仍可能识别不准。

### 网页搜索与引用

- **前端默认开启**“网页搜索”。开启时每次回答必须执行 OpenAI `web_search`，最多 3 次工具调用；关闭后仅使用本地证据。其他 API 客户端未传 `web_search` 时默认关闭。
- **检索反馈**：显示搜索/读取状态、检索时间及可点击的 `[W1]` 等网页引用；引用链接来自 API 的来源注释。搜索失败、工具不可用或未执行时显示错误；没有引用来源时说明证据缺口。
- **证据区分**：`[D1]` 等编号表示本地证据，`[W1]` 等表示网页来源。网页不增加本地统计样本数；检索时间不等于报道发布时间，搜索也不保证资料完整或持续实时。
- **分析要求**：优先使用官方统计、球队公告及可靠媒体，核对赛季、比赛类型和后续伤病更新。网页结果不会自动同步 NBA、写入伤病状态或修改 Elo 胜率。
- **费用与等待**：沿用现有 OpenAI 配置，搜索另计 API 费用；开启搜索的回答总超时为 240 秒，仅本地分析为 150 秒。配置的模型与账户必须支持搜索工具。

### 补齐本地球员统计

只有赛程和比分不能支撑球员得分、效率或组织能力评价。提示缺少统计时：

1. 在“模型分析”选择目标赛季，进入“数据与设置”核对页面显示的同步目标。
2. 同步球队、球员、当前阵容，以及该赛季对应的赛程/赛果。
3. 在第 **06 / 球员逐场统计** 项选择常规赛、季后赛或季前赛，再同步统计。
4. 检查新增、更新、跳过和来源空数据等结果；跳过记录需核对对应比赛、球员和球队是否已同步。完成后重新发送问题。

**“历史常规赛赛果”只补充常规赛比赛，不能代替季后赛统计同步。** 本地为空可能是尚未同步、来源没有返回记录或关联数据缺失，不能仅据此断言该赛季没有比赛。网页搜索可补充有来源的分析材料，完整结构化统计仍需上述同步流程。

### 会话、报告与数据边界

- **会话保留**：切换导航保留当前会话；手动更换球队、球员、赛季或比赛类型会新建会话。按问题自动更新范围不会清空聊天；刷新网页会清空会话。
- **历史长度**：前端从用户消息和已完成的助手回答中选取最近 8 条，每条最多 3500 个字符，连同当前问题发给回答模型；中断或失败的助手回答不作为历史传递。
- **报告导出**：回答下方展示证据、数据截止时间、样本数和边界。“导出 Markdown 报告”下载回答与本地/网页来源清单；未完成回答标注为部分结果。
- **本地证据**：最多 200 场比赛、最近 10 场近况、40 条新闻；比赛仅使用已结束且开赛至少 6 小时的记录。当前阵容是最后同步结果，不等于历史赛季名单；统计按历史所属球队分组，缺失值不作零值。
- **模型与费用**：使用后端 `OPENAI_API_KEY` 和 `OPENAI_MODEL`。每次发送会将所选对象的本地资料与近期对话发给 OpenAI，并产生 API 费用；密钥只保留在后端，调用使用 `store=False`。
- **预测边界**：分析回答不改变 Elo 概率。旧伤病、待审核事件、恢复训练与确认复出需分别判断。
- **加载更新**：前端刷新即可加载新版界面；后端未使用自动重载时需重启。当前分析接口不需要新增数据库迁移。

## 数据来源和更新方式

| 数据 | 来源或处理方式 | 是否用于当前球队胜率 |
| --- | --- | --- |
| 球队目录、赛程、主客场、时间、比分 | `nba_api` 目录和 NBA 数据接口，手动同步 | 主客场与历史胜负参与计算 |
| 历史常规赛赛果 | NBA Stats `LeagueGameLog` | 参与 Elo 更新 |
| 球员资料、阵容、比赛统计 | NBA 同步接口 | 计算分钟和得分暴露；模型验证通过后才影响胜率 |
| 最近 10 场胜率、休息天数 | 从已同步赛果计算 | 仅展示 |
| 新闻、伤病、复出、交易 | ESPN RSS 摘要、ESPN 伤病列表、NBA 官方 PDF 与手动事件 | 核验后的伤病/限时进入特征；交易、教练等事件目前只作上下文 |
| 分析窗口网页资料 | OpenAI `web_search` 返回的网页与引用 | 仅用于分析回答，不写入预测特征 |
| Polymarket 买卖价、订单簿深度、报价时间 | 按 Token ID 请求公开 CLOB 订单簿 | 用于市场比较与风控，不改变模型概率 |

**新闻与伤病默认每 15 分钟采集一次，仅在后端运行时执行。** 采集保存原始来源版本，未来 48 小时内的常规赛/季后赛自动保存赛前特征快照，不自动改写已保存的预测。赛程、球员统计及 Polymarket 不在此定时任务内；仍未使用 WebSocket。

## 当前预测模型

实现见 [Elo 引擎](backend/app/intelligence/engine.py)。

- 每队初始评分为 **1500**，按时间顺序处理已结束的常规赛和季后赛。
- 用赛前预期与实际胜负更新评分；当前只使用胜负，不使用比分差。
- 默认更新系数 `K=20`，主场加分 `65`；跨赛季保留与 1500 差距的 `75%`。参数可在配置中覆盖。

```text
主队胜率 = 1 / [1 + 10^(-(主队 Elo - 客队 Elo + 主场加分) / 400)]
客队胜率 = 1 - 主队胜率
评分变化 = K × (实际胜负结果 - 赛前预期胜率)
```

两队评分均为 1500 时，默认公式输出主队约 **59.2%**、客队约 **40.8%**。这是参数产生的基线，不是已经验证的真实胜率。

**参数尚未拟合、概率尚未校准。** 缺少历史赛果时仍使用初始评分，输出缺少球队区分度；双方各至少 10 场历史是默认模拟信号条件，并不是阻止所有低样本概率输出的门槛。

Elo 回测提供 Brier Score、Log Loss、准确率、校准误差和 ROC-AUC。赛果暂按开赛后 6 小时可用；仅有比赛日期的历史记录使用估算时间，因此尚不能严格复现历史数据可用性。后端 `/intelligence/backtest` 仍评估 Elo；前端入口已移除。伤病残差模型另在「新闻与伤病」中训练和进行时间留出验证。

## 新闻、伤病及长期事件

实现见 [事件上下文](backend/app/news/context.py)，完整类型与解除规则见 [架构说明](docs/architecture.md)。

- **普通新闻**：默认保留最近 7 天，`NEWS_RECENT_HOURS=168`；最多展示 30 条普通新闻。
- **长期事件**：结构化伤病、停赛、交易、角色变化、上场时间限制等，不因超过新闻窗口而丢弃，单独处理后展示。
- **解除或更新**：通过 `POST /api/v1/news/events` 追加同一球员的复出、解除或更新事件，按事件类别和比赛范围替换旧状态。原始报道仍保存在数据库中。
- **待复核**：超过 `NEWS_REVIEW_AFTER_HOURS=168` 未更新的长期事件会标记待复核；缺少球员关联的球员长期事件也需复核。没有解除记录不等于确认仍然缺阵。
- **比赛范围**：绑定具体比赛的事件只用于该场；跨比赛长期事件应通过球员或球队关联录入。
- **时间约束**：事件发布时间和入库时间均不得晚于预测时点，未来信息不进入当时的上下文。

### 自动采集与审核的使用方法

1. 在「数据与设置」同步球队、球员和当前阵容。同步上一赛季常规赛赛果及球员逐场统计，补齐分钟和得分数据。
2. 打开新增的 **「新闻与伤病」**，点击「立即采集」；默认自动采集开启，每 15 分钟一轮。查看各来源的成功、失败及记录数。
3. ESPN 伤病接口按球员姓名和当前球队唯一匹配，不把 ESPN 编号当成 NBA 编号。已准确匹配的结构化状态直接核验；未匹配事件需先补齐目录，再采集一次并审核。
4. 配置已有 `OPENAI_API_KEY` 后点击「提取待处理新闻」。使用 Responses Structured Outputs 提取事件和原文引用，每轮默认最多 3 篇摘要；**自动模型提取默认关闭**，开启或手动提取会消耗 API 额度。
5. 新闻提取结果必须通过精确原文引用、球员姓名、球队、日期检查，随后进入待审核区。核对引用和来源全文，批准或排除事件；批准时间也参与时序约束。
6. NBA 官方目录失败或未发布时，页面保留错误状态；可导入 `ak-static.cms.nba.com/referee/injury/Injury-Report_...pdf` 官方链接。报告必须解析出日期、对阵、球队、球员和状态，禁止把空报告或未提交当成健康。
7. 在比赛页面重新运行 Agent，查看 **「伤病影响量化」**。刷新只读取已有快照，不自动重新预测。

采集结果、原始文本版本、审核时间、模型结果与赛前快照保存在 `backend/data/news/archive.sqlite3`，原始 PDF 保存在同目录 `reports/`。不新增 PostgreSQL 表，也不需要新的 Alembic 迁移；已有手动 `news_events` 继续提供上下文。不要把测试档案当作真实训练样本。

### 量化口径与胜率修正

- **通常分钟/得分**：使用赛前可获知、同一当前球队近 180 天内最近 10 场已出场比赛，至少 5 场。缺少数据不补零冒充完整统计。
- **缺阵**：新鲜、已核验的 Out 或停赛状态对应 0 分钟；缺阵分钟和通常得分属于暴露指标，不等于球队净得分损失或球员因果价值。
- **出场不确定**：questionable/doubtful/probable 显示 0 至通常分钟的情景范围，不擅自赋予固定出场概率。
- **限时与恢复**：只使用原文明确的分钟数字。恢复训练不等于可出场；可出场不解除独立的分钟限制或停赛。新版完整官方报告移除球员时标记待复核，不继续视为确认缺阵，也不直接断言已痊愈。
- **时效**：伤病状态默认超过 `INJURY_STATUS_MAX_HOURS=24` 小时即须复核；长期事件仍保留。跨比赛的全局报告不会被当成 48 小时以后某场比赛的确定状态。
- **模型**：拟合 `logit(p) = logit(Elo p) + β·伤病暴露差`。四个特征为缺阵分钟差、不确定分钟差、受限分钟差和缺阵得分差，分别按 240 分钟/120 得分归一化。系数由数据拟合，大语言模型不生成胜率。
- **启用门槛**：默认至少 200 场真实赛前快照，双方新鲜官方报告完整，球员统计足够，且无待复核/未匹配的相关伤病。按比赛时间分成 80% 训练、20% 留出验证，并排除边界前 6 小时尚不可获知的赛果。
- **验证与回退**：固定 L2 正则，不在验证集调参；验证集 Brier 与 Log Loss 均优于 Elo 才保存可用模型。未验证、缺少本场数据或特征超出训练范围时回退 Elo。通过该验证仍不等于已校准，也不证明盈利。

**当前真实模型尚未训练完成。** 不能用今天的伤病倒填过去比赛。目前可使用自动采集、事件审核和分钟影响展示；替补补偿、阵容协同及交易/教练事件的胜率系数尚未实现。原有球员 Forecaster 与此球队概率流程独立。

## Polymarket 报价和概率

1. 在前端选择与市场对应的同一场比赛。
2. 将“数据来源”切换为“Polymarket 实时报价”。
3. 选择主队胜或客队胜，输入该胜出方向的 **CLOB Token ID**。
4. 核对比赛日期、对阵、胜者合约与方向，勾选确认后点击“读取订单簿”。
5. 需要更新时再次读取，并重新运行 Agent 生成最新市场比较。

Token ID 是特定结果方向的公开编号，一般为长数字串。通过市场详情的 `outcomes` 与 `clobTokenIds` 按相同位置对应；它与 API 密钥不同。

- 读取内容为最佳买价、最佳卖价、最优卖价档位的美元深度和订单簿时间。
- 后端保存的市场隐含概率采用 `(最佳买价 + 最佳卖价) / 2`；当前比较界面主要展示 Ask 和模型概率。
- Polymarket 网页在价差过大时可能使用最新成交价，网页显示值可能与本项目的中间价不同。
- 页面中的灰色输入示例不是已抓取报价；手动研究报价不能触发允许开模拟仓位的信号。
- 页面选项中的“实时”指点击时读取订单簿快照，尚未实现持续自动更新、自动寻找比赛合约或价格走势图。
- 季前赛可以读取市场报价，但不能运行当前球队预测模型。

参考：[Polymarket 市场详情与 Token 对应关系](https://docs.polymarket.com/market-data/market-details)、[官网价格显示规则](https://help.polymarket.com/en/articles/13364488-how-are-prices-calculated)。

## 模型局限与后续优化

球队胜率差距是否合理，需要用历史样本、校准曲线和基线对照判断。当前模型使用的信息有限，不能仅凭输出一个百分比认为已经充分利用数据。

后续需要完善的部分：

1. 积累真实赛前伤病快照，补齐攻防效率、替补补偿和阵容协同特征。
2. 在已实现的事件事实提取、原文核验和状态审核基础上，扩展交易、教练变化等事件的量化特征，并用真实历史数据验证影响。
3. 在已区分恢复训练、确认复出、出战存疑和分钟限制的基础上，完善替补补偿与阵容交互，评估伤病影响是否已部分反映在 Elo 中，避免重复计算。
4. 拟合模型参数、评估更完整的概率模型并进行时间顺序验证与概率校准，检查是否优于简单基线及市场概率。
5. 扩展已有新闻调度，增加赛程/统计更新、自动合约匹配与报价更新，让变更触发可追踪的重新预测。

## 保留的后端模拟交易接口

- 前端不再展示模拟交易页面、模拟金额或入场按钮，也不请求模拟仓位列表；既有后端接口与记录保留。
- 后端仅记录研究仓位，没有钱包、交易签名或真实下单模块。
- 默认要求双方各至少 10 场历史、预测和报价不超过 15 分钟、买卖价差不超过 0.05、最优卖价深度至少 1000 美元，以及成本缓冲后的概率差至少 0.05。
- 默认单笔模拟金额上限 100 美元，总敞口上限 500 美元；入场时再次检查最新预测、报价、比赛状态及重复仓位。
- 成本缓冲是近似值；模拟结算依据 NBA 比分，未完整覆盖取消、作废及交易所不同裁定规则。
